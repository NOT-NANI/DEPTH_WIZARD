# DepthWizard Frontend

A modern, interactive research frontend for the DepthWizard single-image relative-depth and calibrated-height estimation prototype.

## Architecture & Technology Choice

- **Stack**: Vanilla HTML5, modern ES modules, and Vanilla CSS with CSS custom properties.
- **3D Visualization**: Three.js (r160) and OrbitControls vendored locally in `frontend/vendor/three/` (matching the version generated by the backend's `terrain_viewer.html`, without external CDN dependency for local rendering).
- **Backend Communication**: Clean, reusable API client in `frontend/js/api.js` interfacing with the Python backend via CORS on localhost. Real upload progress is tracked via `XMLHttpRequest.upload`, with honest waiting states during inference (no fake percentage counters).
- **Rationale**: The project had no existing JavaScript/Node tooling or package manager installed in the environment (no `npm` or `node`). Using standard ES modules and native Web APIs requires zero build steps, zero bundle overhead, and zero external JS package managers, while providing instantaneous browser loading, full TypeScript-friendly modularity, and high maintainability.

## Backend Service Requirement

The backend must be running at `http://127.0.0.1:8765`:

```bash
./venv/bin/python scripts/run_demo.py --host 127.0.0.1 --port 8765
```

The frontend backend URL is configured in `frontend/config.js` (`API_BASE_URL`).

## Running the Frontend

Serve the `frontend/` directory with Python's built-in HTTP server:

```bash
./venv/bin/python -m http.server 5173 --directory frontend
```

Then open `http://127.0.0.1:5173` in any modern web browser (Chrome, Safari, Firefox, Edge).

## Features

1. **Primary Workflow**:
   - **Step 1: Image**: Drag-and-drop or browse PNG, JPG, or RGB GeoTIFF (when Rasterio is installed). Shows image dimensions, file size, and decoded input preview.
   - **Step 2: Height Interpretation**: Select between:
     - *Stage 12 validation-calibrated estimate* (`m (estimated)`): uses frozen Experiment B validation-scene calibration.
     - *Unitless relative output* (`unitless`): direct normalised model output without metric mapping.
     - *Custom scale / shift*: user-defined linear transformation with explicit metric unit confirmation.
   - **Step 3: Process**: Clear upload progress bar followed by an honest inference waiting timer.
   - **Step 4: Inspect**: 
     - 2D map viewer with layer toggles (RGB input, relative depth, height map, optional DSM, slope), opacity blending, and legend bounds.
     - Interactive 3D terrain viewer powered by the `/api/runs/{id}/surface` binary float32 endpoint with OrbitControls, vertical exaggeration slider, color modes (RGB texture, colormap ramp, slope degrees), and sensible camera framing.
     - Point inspector: click anywhere on the 2D map or 3D terrain to trigger `/api/runs/{id}/sample` for exact pixel coordinates, relative depth, calibrated height, and optional slope/DSM readings. Also supports manual coordinate entry and keyboard crosshair navigation.
   - **Step 5: Export**: Categorized file downloads (data grids, preview images, 3D textured mesh bundle, metadata, and full result ZIP). Unavailable artifacts (e.g. GeoTIFF when Rasterio is missing) are clearly distinguished.
2. **Scientific Integrity**:
   - Relative depth is explicitly marked as `unitless`.
   - Calibrated heights are prominently labeled as `estimates`, not surveyed elevations.
   - No CRS or geospatial transform is invented for PNG/JPG inputs.
   - GeoTIFF and DEM capabilities are dynamically disabled when Rasterio is absent on the backend.
